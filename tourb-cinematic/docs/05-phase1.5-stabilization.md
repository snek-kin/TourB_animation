## 5. Что исправлено / изменено (кратко)

- `THREE.Clock` → **`THREE.Timer`** (`connect(document)`): на скрытой вкладке dt = 0; анимации получают dt ≤ 0.1 с, статистика — настоящий интервал; мастер-таймлайн сцены ведётся вручную → пауза/перемотка не зависят от FPS.
- **Прогрев сцены** под «шторой»: компиляция шейдеров, загрузка текстур, пробный кадр с включёнными эффектами.
- **ShaderGuard**: сломанный шейдер находится (диагностика принудительно заполняется через `getUniforms()` — иначе three делает это лениво, на первом кадре), объект отключается через слой, пользователю — уведомление. Проверено тестом со специально сломанным шейдером: найден, отключён, спама ошибок 0.
- **Качество адаптивно по ступеням**: плотность частиц (1 → 0.75 → 0.55 → 0.4), затем pixelRatio до 0.75; снижение только после двух подряд плохих окон по 2 с, первое окно после смены сцены не считается. Одиночный тяжёлый кадр на старте больше не закрепляет низкое разрешение. Возврата вверх нет — осознанно: качество не должно «плавать» во время фильма.
- **MSAA по умолчанию только при DPR < 1.75** (на плотных экранах он не виден и дорог); `?aa=0|1` переопределяет.
- Громкие сообщения об ассетах; `?bench`; уведомления в кадре; троттлинг отладки (4 Гц); `[hidden]` в CSS.

## 7. Ревью шейдеров на совместимость с реальными GPU

- **Лимит размера точки.** Драйверы обрезают `gl_PointSize` до `ALIASED_POINT_SIZE_RANGE[1]` (у части интегрированных и мобильных GPU это 64 px, у SwiftShader — 1023).
  Раньше размер клампился константой 40–72 px без учёта лимита. Теперь `uMaxPx = min(3 % высоты кадра, лимит GPU)`. Фактический лимит читается один раз на рендерер.
- **Точность.** Вершинные шейдеры — `highp` по спецификации. Фрагментные шейдеры эффектов используют только малые значения (`vGlyph` ≤ 32, яркости 0–2): на GPU без `highp` во фрагментах (`mediump`) результат тот же. Время `uTime` растёт линейно: при длительности сцены ≤ 230 с и пересоздании материалов при перезапуске потери точности нет.
- **Синтаксис GLSL** валиден для WebGL2 (three r187 — только WebGL2); директивы `#include` — в начале строки (причина прежней ошибки); ветвление `return` до `gl_Position` в вершинном шейдере дождя допустимо.
- **Не проверено:** реальные драйверы (NVIDIA/AMD/Intel/Apple/Adreno/Mali), Safari/Firefox. Проверен только ANGLE/SwiftShader.

## 8. Полнота `dispose`

Тест `audit.py` подписывается на события `dispose` **всех** геометрий, материалов, текстур (включая текстуры в uniforms шейдеров) и `InstancedMesh` каждой сцены, затем вызывает `scene.dispose()`:
результат — **0 неосвобождённых несовместных ресурсов** в `val-digital` и `val-map`. Исключение (намеренное): три общие геометрии `GlowMarker` помечены `shared` и живут до закрытия страницы.
Найденный и исправленный пробел: `InstancedMesh` не освобождал буферы экземпляров. **Не покрыто тестом:** `AssetManager.release()` и `AudioManager.dispose()`.

## 11. Оставшиеся проблемы и ограничения

1. **Реальный FPS на видеокарте не измерен.** Запустить `index.html?bench` в Chrome/Edge с аппаратным ускорением; если в окне «программный рендер» — ускорение выключено, замер недействителен.
2. Непонятная разовая остановка 0.6–1.2 с на старте на виду (§4) — причина не установлена.
3. Safari/Firefox, мобильные и интегрированные GPU не проверялись; лимиты драйверов только прочитаны в коде.
4. `matchCut` — заглушка; `AudioManager` не тестировался; KTX2/Meshopt не подключены.
5. Адаптивное качество только вниз: если ПК кратковременно перегружен, качество остаётся сниженным до перезагрузки страницы (смягчено требованием двух плохих окон).
6. Валидационные сцены — не сцены фильма, 3D-моделей в них нет.
7. Расхождение «бриф ↔ презентация» (переводчик, Smart Deals, живой город) по-прежнему требует решения команды (`docs/01-analysis.md`).

## 12. Готовность к первой производственной сцене

**Фундамент готов к Phase 2 с одной оговоркой:** прежде чем строить дорогие сцены, нужно получить `?bench` с вашего компьютера.
Если там ≥ 50 FPS и «1% low» ≥ 30 — начинаем со сцены «Цифровой мир». Если ниже — сначала смотрим, что именно: плотность частиц, MSAA, разрешение.
